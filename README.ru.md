# Основание

*Русская версия. English: [README.md](README.md).*

**Для кого.** Для человека, который хочет навести в своей жизни порядок и держать его сам, без надзирателя: ежедневно делать то, что развивает, и не делать того, что разрушает. Приложение личное — оно не про соревнование и не про отчётность перед кем-то.

Оно решает три задачи.

**Дисциплина.** У дня есть структура: утренний, вечерний и ночной ритуалы. Бот приносит каждый в своё окно — не в ленту, которую надо открыть, а в чат, где ритуал закрывается одним касанием. Норма на день подстраивается под то, как человек идёт: после пропусков падает до минимума, чтобы было с чего начать, при устойчивой цепи растёт. Три оболочки — Тело, Разум и Дух — растут от действий и проседают от простоя, а общая Сила считается так, что накачать одну и вытянуть за её счёт остальные нельзя.

**Ограничение.** Часть практики — это не делать. Пост задаёт окно еды и запреты на срок, и пока он идёт, интерфейс сам обесцвечивается до монохрома: приложение снижает собственную сенсорную награду, а не только требует воздержания в чём-то другом. Декларация на завтра проходит через валидатор, который отклоняет пункты про лень, потребление и удовольствие. Срыв фиксируется как опыт и не отнимает уровень — наказания здесь нет, есть возврат.

**Вживление.** Философия Основания — не справочник, который читают один раз. Её тезисы разобраны на карточки и возвращаются интервальным повторением: карточка показывает начало тезиса и раскрывает текст только после попытки вспомнить, забытое приходит завтра, вспомненное — всё реже. Рядом След: спираль прожитых дней, где яркость точки — Сила того дня, и недельный Свиток. Смысл в том, чтобы текст перестал быть текстом и стал тем, из чего человек действует не задумываясь.

**Как это выглядит.** Telegram-first: бот — основная точка входа, утренние и ночные ритуалы закрываются прямо в чате. Mini App открывается для того, что в чат не помещается: Декларация, Тишина, Пост, Канон, Свиток, След. Сессия заканчивается, когда ритуал выполнен — бесконечной ленты нет по устройству.

Правила механик выведены из [Философии Основания](Философия%20Основания/Философия%20Основания.md) — хранилища Obsidian, лежащего в репозитории. Оно же источник данных для раздела Канон: тексты импортируются в базу и участвуют в повторении. Если нужно понять, *почему* механика устроена именно так, ответ там; ниже — про то, *как* всё устроено технически.

## Стек

| Слой | Что |
|---|---|
| Приложение | Next.js 15 (App Router, RSC), React 19, TypeScript 5.9 |
| Стили | Tailwind v4 (через `@tailwindcss/postcss`) |
| База | Neon Postgres, Prisma 6 (`DATABASE_URL` — пулер, `DIRECT_URL` — миграции) |
| Аутентификация | Telegram initData / Login Widget → собственные JWT на `jose` |
| Telegram | Bot API напрямую, через `fetch` — без библиотеки-обёртки |
| Тесты | Vitest (юниты), Playwright + sharp (визуальные проверки) |
| Хостинг | Vercel, регион `fra1` |

Зависимостей намеренно мало: в serverless каждая лишняя увеличивает холодный старт. Обёртка над Bot API — свои полсотни строк в [lib/bot/api.ts](lib/bot/api.ts), потому что используется пять методов.

## Архитектура

**Воркера нет.** На Vercel нет долгоживущего процесса, поэтому расписание — это HTTP-эндпоинт [app/api/cron/rituals/route.ts](app/api/cron/rituals/route.ts), который каждые 15 минут дёргает внешний пингер (cron-job.org), передавая `CRON_SECRET`. Один тик делает две вещи: раскладывает наступившие окна ритуалов в очередь и отправляет то, что в ней лежит.

**Очередь — таблица.** `OutboxMessage` с уникальным `dedupeKey`: перекрывшиеся тики физически не могут отправить ритуал дважды. Просроченное не догоняется. Состояние очереди смотрится через `npm run outbox`.

**Бот — только webhook.** Поллинга нет (некому поллить). Входящие апдейты принимает [app/api/bot/route.ts](app/api/bot/route.ts), подпись проверяется по `X-Telegram-Bot-Api-Secret-Token`. Привязка вебхука — `npm run bot:webhook -- set`.

**Два входа, один аккаунт.** Из Mini App приходит `initData`, из браузера — Login Widget; у них разные схемы подписи (см. [lib/auth/telegram.ts](lib/auth/telegram.ts)), но пользователь один. Сессия — короткий access-JWT (15 мин) плюс длинный ротируемый refresh; access принимается и из куки, и из `Authorization`, потому что внутри webview Telegram сторонние куки могут блокироваться.

**Доменная логика отделена от экранов.** Всё, что считает состояние — уровни оболочек, Сила как гармоническое среднее, Боль, норма дня, интервалы повторения — лежит в `lib/core/` чистыми функциями и покрыто юнит-тестами. API-роуты только читают базу, зовут эти функции и пишут результат.

## Структура

```
app/                     экраны (RSC) и API-роуты
  api/                   akt, blago, put, dar, tishina, post, slovo,
                         settings, osnashenie, auth, bot, cron, health, version
components/
  triquetra/             SVG-движок Триквестра — геометрия и заливка
  <раздел>/              клиентские компоненты соответствующих экранов
lib/
  core/                  доменная логика: оболочки, Сила/Боль, расписание, SRS
  canon/                 разбор Obsidian-хранилища в Канон, ссылки, релевантность
  auth/                  проверка подписей Telegram, сессии
  bot/                   Bot API и тексты сообщений
  sections.ts            карта разделов — источник для нижней панели и «Разделов»
prisma/schema.prisma     модель данных
scripts/                 служебные скрипты (см. ниже)
Философия Основания/     исходное хранилище Obsidian
docs/                    план работ и список отложенного
```

Триквестр ([components/triquetra/geometry.ts](components/triquetra/geometry.ts)) — не картинка, а вычисляемый прибор: три окружности `R = 1` с центрами на радиусе `D = 0.86`. Условие `R > D` обязательно — оно уводит внутренний конец лепестка за центр и создаёт общее ядро. Координаты выводятся кодом и покрыты тестами.

## Запуск

```bash
npm install                 # postinstall сам делает prisma generate
cp .env.example .env        # заполнить Neon, токен бота, JWT_SECRET, CRON_SECRET
npx prisma migrate dev
npm run canon:import        # залить Канон из хранилища в базу (идемпотентно)
npm run dev
```

Минимум для локальной работы: `DATABASE_URL`, `DIRECT_URL`, `JWT_SECRET`. Telegram-переменные нужны, только если трогаете бота или вход; `NEXT_PUBLIC_APP_URL` по http допустим лишь для localhost — Telegram требует HTTPS.

Для бота на локальной машине нужен публичный HTTPS-туннель: `npm run bot:webhook -- set https://<туннель>`, а `npm run bot:webhook` без аргументов покажет, чей это токен и куда сейчас привязан вебхук.

Хук `.githooks/pre-commit` поднимает патч-версию в `package.json` на каждом коммите (версия видна внизу экрана приложения). Включается один раз: `git config core.hooksPath .githooks`.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` / `build` / `start` | обычный цикл Next.js |
| `npm test` | 282 юнит-теста: геометрия, доменная логика, разбор Канона |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run db:push` | `prisma migrate dev` — миграция на дев-базе |
| `npm run db:migrate` | `prisma migrate deploy` — на боевой |
| `npm run canon:import` | импорт хранилища в базу |
| `npm run canon:report` | состав Канона, объём тезисов, битые ссылки |
| `npm run outbox [-- дней]` | что ушло, что застряло, на чём споткнулось |
| `npm run bot:webhook -- [info\|set\|delete] [url]` | состояние и привязка вебхука |
| `npm run check:* -- <url>` | сквозные проверки в живом браузере |
| `npm run shot -- <url> <файл.png>` | скриншот экрана |

`check:*` — это Playwright-проверки против запущенного приложения, по одной на раздел (`fill`, `artifact`, `zavety`, `put`, `sled`, `duhdar`, `tishina`, `post`, `fasting`, `slovo`, `cron`, `bot`, `settings`, `osnashenie`). Они ловят класс ошибок, недоступный юнит-тестам: например, математика заливки Триквестра верна, а ломается система координат, в которой браузер разрешает содержимое `<mask>`. Проверки смотрят на пиксели.
